## 7. Timestamp handling
Two source clocks exist and are **not** interchangeable: smartphone files carry an elapsed-millisecond counter plus a wall-clock `DATE` string (`YYYY-MM-DD HH:MM:SS:mmm`, milliseconds after a colon); vehicle files carry seconds-since-midnight with no date.

Canonical records keep `source_time_s` exactly as written and add `analysis_time_s`, the continuous clock used for segmentation and alignment:

| analysis_time_source | Files |
|---|---|
| `time_of_day` | 323 |
| `wall_clock` | 241 |

**Why the wall clock wins for smartphone streams.** 15 file(s) restart the elapsed counter mid-recording (e.g. `S-S2.csv` drops from t=186.3 s to t=0.010 s at row 1863) while their `DATE` column runs straight through. Segmenting on the counter would fragment one continuous drive, and *sorting* by it would interleave two trips into a trajectory that never happened. The counter resets are reported as `source_counter_reset_count` but are not treated as trip boundaries.

- Duplicate timestamps: 162,412 row(s) across 27 file(s). **All retained**, flagged `DUPLICATE_TIMESTAMP`. No row was dropped.
- Non-monotonic rows: 0 across 0 file(s), flagged `NON_MONOTONIC_TIMESTAMP`. Where they occur, rows are stably sorted **within a segment only** — never across a boundary, so distinct trips can never be merged.
- **No resampling and no 10 Hz assumption.** Every sample keeps its own timestamp.

## 13. Duplicate-content split strategy
Phase 1 found 235 byte-identical duplicate files. Phase 2 found **15 further groups whose files differ only in header labels while their data rows are byte-identical** — 314 distinct payloads behind 329 distinct file hashes. Splitting on the file hash alone would therefore still leak.

Splits group on a **payload hash** (SHA-256 of everything after the header line), then take the transitive closure with shared `(dataset_family, session_id)`. That closure matters: the same session is filed under several family directories, and a shared payload chains those copies into one group.

Whole groups are then packed **largest-first into whichever split is furthest below its target row count**. Hashing groups onto cumulative ratio boundaries was tried first and rejected: it balances *group counts*, and because group sizes span orders of magnitude it left the test split with under 1% of the rows. Determinism is kept by sorting on `(-rows, sha256(seed:group_key), key)`, so nothing depends on wall-clock or dict iteration order.

Default ratios: {'train': 0.7, 'validation': 0.15, 'test': 0.15}.

| Split | Segments | Rows | Duration (h) |
|---|---|---|---|
| test | 135 | 1,378,465 | 40.9 |
| train | 268 | 6,432,968 | 178.6 |
| validation | 182 | 1,378,323 | 38.8 |

- Groups: **115** covering 585 segments.
- Leakage violations: **0** (a payload or session appearing in more than one split).

**Content-level audit.** The payload hash sees only byte-identical data rows, so two copies of one recording written with different numeric formatting would look distinct to it. Every written segment is therefore fingerprinted a second time from its *parsed* sensor values (rounded to 1e-6) and the split re-checked against that equivalence: **314** segment(s), **256** distinct content group(s), of which **58** hold more than one segment despite differing payload hashes. Violations: **0**.

Segments are assigned whole, so overlapping windows drawn from one trip can never straddle a split boundary. Rows and windows are **never** split randomly.

## 14. ML-ready data contract
Canonical data is stored as **Parquet** (snappy), one file per segment under `data/processed/io_vnbd/<stream>/`. Parquet was chosen for columnar reads (a model needing six channels does not pay for sixty), preserved numeric dtypes, good compression on this volume, first-class Windows/pandas/pyarrow support, and chunked reading. Pickle was rejected outright for multi-million-row data.

Sequence windows are **generated on demand**, not materialized, so a later experiment can change the geometry without regenerating a corpus. Defaults: `duration_seconds=5.0`, `stride_seconds=0.1`, `min_coverage=0.8` — a starting point, not a finding.

**Causality is enforced:** for a target at time *t*, the window contains only samples with time ≤ *t*. A test asserts no future sample can enter a window.

## 18. Limitations
- **Synchronization is inferred, never documented.** No ground-truth alignment exists in IO-VNBD, so even a confirmed pair rests on a correlation argument.
- **Gyroscope axis semantics are unverified.** Positional mapping is well evidenced; the yaw/pitch/roll labels are not, and no device→vehicle rotation is estimated here.
- **The satellite field's `a / b` reading is an interpretation.** The raw string is preserved so it can be revisited.
- **Timezone is unresolved.** `timestamp_utc` carries the smartphone's wall clock as written; whether it is UTC or local is not stated by the dataset.
- **Sub-hour offsets and drift remain in the data.** Phase 2 measures them and leaves the streams untouched.
- **Segment boundaries are a threshold choice.** The rule is documented and reproducible, but a different threshold would yield different trips.
- **No GNSS-denial data exists.** Anything resembling an outage must be synthesized later and labelled synthetic.
